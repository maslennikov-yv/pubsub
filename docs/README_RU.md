**Публикация/подписка с ограничением по времени, подходит для опроса группы датчиков.**

Небольшой потокобезопасный pub-sub-хаб на Go, подписчики которого ждут **набор событий по ключам** с таймаутом. Создан для сценариев вроде опроса группы датчиков: подписаться на ключ каждого датчика, публиковать показания по мере поступления, а `Wait` вернётся, как только у каждого ключа появится значение или истечёт таймаут — что наступит раньше.

Реализация детерминирована: каждая операция выполняется внутри единственной критической секции хаба, поэтому итог любого сценария зависит только от порядка вызовов, а не от планировщика горутин. Нет фоновых горутин, sleep'ов, логов и паник.

[English version](../README.md) (каноническая версия — английская, русская может отставать.)

## Установка

```sh
go get github.com/maslennikov-yv/pubsub@latest
```

Требуется Go 1.26 или новее. Зависимостей вне стандартной библиотеки нет.

## Ключевые особенности

- **Простой API.** Создать хаб и подписчиков, подписаться по строковому ключу, ждать с таймаутом, публиковать с булевым результатом.
- **Ранний возврат или частичный результат.** `Wait` возвращается сразу, как только у каждого подписанного ключа есть значение; по таймауту возвращает то, что успело прийти.
- **Побеждает последнее значение.** Если ключ публикуется несколько раз, пока подписчик жив, сохраняется только самый свежий payload.
- **Точная обратная связь издателю.** `Publish` возвращает `true` тогда и только тогда, когда хотя бы один живой подписчик сохранил payload. `true` гарантирует, что payload попадёт в результат `Wait` этого подписчика (если его не перезапишет более поздняя успешная публикация); `false` гарантирует, что его никто не увидел.
- **Синхронный идемпотентный `Close`.** Немедленно пробуждает все заблокированные `Wait`, удаляет все топики, всегда возвращает `nil`.

## Пример использования

```go
hub := pubsub.NewPubSub()
defer hub.Close()

subscriber := hub.NewSubscriber()
subscriber.Subscribe("foo")
subscriber.Subscribe("buz")

// Издатели обычно работают в других горутинах, пока Wait заблокирован.
go func() {
    hub.Publish("foo", map[string]int{"foo": 90})  // true
    hub.Publish("foo", map[string]int{"foo": 100}) // true, перезаписывает 90
    hub.Publish("bar", map[string]int{"bar": 50})  // false: "bar" никто не слушает
}()

// Ждём до 1 секунды. "buz" так и не приходит, поэтому Wait вернётся по таймауту.
results := subscriber.Wait(time.Second)

// results == map[string]any{"foo": map[string]int{"foo": 100}}
// "buz" отсутствует: для него ничего не публиковалось.
// "foo" содержит последнее значение (100, а не 90).
```

Запускаемая версия — в [`examples/sensors/main.go`](../examples/sensors/main.go); детерминированный вариант — godoc-пример `Example` в [`example_test.go`](../example_test.go).

## Семантика

### Жизненный цикл подписчика

Подписчик **жив** с момента `NewSubscriber` до **завершения**. Завершение — единственный атомарный терминальный переход: подписчик перестаёт принимать сообщения и удаляется из всех топиков (опустевшие топики удаляются). Оно наступает ровно в одном из моментов:

1. **Вход в `Wait`**, если хаб закрыт, таймаут `<= 0` или подписчик уже *полон* (у каждого подписанного ключа есть значение; подписчик без подписок тривиально полон и возвращается сразу).
2. **`Publish`, делающий подписчика полным, пока `Wait` заблокирован.**
3. **Истечение таймера** заблокированного `Wait`.
4. **`Close`.**

Полнота *до* вызова `Wait` — **не** триггер: подписчик остаётся жив, принимает перезаписи и новые `Subscribe`. Поэтому `Subscribe(a); Publish(a); Subscribe(b)` работает ожидаемо: `Wait` потребует и `a`, и `b`.

Подписчик **одноразовый**. После завершения `Subscribe` — no-op, а каждый следующий `Wait` немедленно возвращает тот же снимок, не блокируясь. Параллельные вызовы `Wait` на одном подписчике возвращают этот снимок, как только первый из них завершит подписчика, то есть действует самый короткий таймаут.

### `Subscribe(key)`

Регистрирует интерес к `key`. No-op для `nil`-подписчика, закрытого хаба, завершённого подписчика или уже подписанного ключа. Действует и пока `Wait` этого подписчика заблокирован — расширяет набор ключей, которых требует `Wait`.

### `Publish(key, payload) bool`

Доставляет `payload` каждому живому подписчику `key`, заменяя предыдущее значение по этому ключу. Возвращает `true`, если получил хотя бы один подписчик, и `false`, если хаб закрыт или подписчиков нет.

Следствия:

- **Побеждает последнее, пока подписчик жив.** Перезаписи принимаются до завершения подписчика.
- **Если `Wait` уже вызван, он возвращается в первый момент полноты**, и с этого момента подписчик ничего не принимает (`Publish` вернёт `false`, если он был единственным подписчиком).
- Подписчик, который собрал всё, но **так и не вызвал `Wait`, остаётся зарегистрированным** до `Close`; публикации ему продолжают возвращать `true`. Очистка происходит только при `Wait` или `Close`.

### `Wait(timeout) map[string]any`

Блокируется, пока у каждого подписанного ключа не появится значение, не истечёт `timeout` или не закроется хаб; затем завершает подписчика и возвращает **копию** результатов. Ключи, по которым ничего не пришло, отсутствуют. `timeout <= 0` возвращает сразу то, что уже есть. `Wait` у `nil`-подписчика возвращает пустую map.

Точка линеаризации `Wait` — его финализация. Payload, опубликованный в крошечном окне между срабатыванием таймера и финализацией, входит в результат, и тот `Publish` вернул `true`, поэтому результат и возвращаемые значения всегда взаимно согласованы.

### `Close() error`

Помечает хаб закрытым, завершает всех зарегистрированных подписчиков (немедленно пробуждая заблокированные `Wait` с тем, что они успели собрать) и удаляет все топики. Синхронный, идемпотентный, O(подписчиков), всегда возвращает `nil`. После него `NewSubscriber` возвращает `nil`, `Publish` — `false`, `Subscribe` — no-op, `Wait` никогда не блокируется.

## API

| Метод | Назначение |
|---|---|
| `NewPubSub() *PubSub` | Создать открытый хаб. |
| `(*PubSub).NewSubscriber() *Subscriber` | Создать живого подписчика; `nil` после `Close`. |
| `(*Subscriber).Subscribe(key string)` | Зарегистрировать интерес к ключу. |
| `(*Subscriber).Wait(timeout time.Duration) map[string]any` | Собрать результаты. |
| `(*PubSub).Publish(key string, payload any) bool` | Доставить payload. |
| `(*PubSub).Close() error` | Завершить работу; всегда `nil`. |
| `(*PubSub).IsClosed() bool` | Вызывался ли `Close`. |
| `(*PubSub).GetTopicCount() int` | Ключи хотя бы с одним живым подписчиком. |
| `(*PubSub).GetSubscriberCount(key string) int` | Живые подписчики ключа. |
| `(*PubSub).Hash(key string) string` | Hex-MD5 ключа для имён топиков фиксированной длины (не криптографический примитив). |

## Гарантии

- **Потокобезопасность.** Все методы можно вызывать конкурентно из любых горутин. Всё состояние охраняет единственный `RWMutex` хаба; иерархии блокировок, которую можно инвертировать, нет. Обратная сторона: все вызовы, включая `Publish` по разным ключам, сериализуются в пределах хаба; если нужен параллельный fan-out, разнесите нагрузку по нескольким экземплярам `PubSub`.
- **Нет скрытой конкурентности.** Библиотека не запускает горутин и не спит. `Close` и финализация `Wait` синхронны.
- **Нет паник и логов.** Для значений, полученных из `NewPubSub` и `NewSubscriber` (включая `nil`-подписчика после `Close`), невалидные операции — безопасные no-op с определённым результатом. Zero-value структуры и `nil *PubSub` не поддерживаются.
- **Память.** При завершении подписчик отвязывается от всех топиков; пустые топики удаляются. Подписчика, который так и не вызвал `Wait`, освобождает `Close`.

## Сценарии применения

1. **Сбор данных с датчиков.** Опросить несколько датчиков и собрать ответы в заданном окне времени.
2. **Fan-in с таймаутом.** Дождаться ответов от нескольких сервисов, допуская частичный набор.
3. **Агрегация событий.** Собрать последнее состояние из нескольких источников перед обработкой.
